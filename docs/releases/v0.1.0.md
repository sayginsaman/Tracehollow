# Tracehollow 0.1.0

The first release. Tracehollow has been developed in public since 2026-09-17 and is tagged here for
the first time, with continuous integration green on a hosted runner and six of its nine connectors
checked against their real sources.

Tracehollow is a self-hosted OSINT investigation workspace: cases and evidence in PostgreSQL,
collection in isolated containers, and optional evidence-grounded answers from a local model.

## What is in this candidate

Phases 0 to 5 of [PRD.md](../../PRD.md) are implemented and verified in the running stack:

- **Foundation.** Docker Compose stack, first-run setup, server-side sessions with CSRF
  protection, migrations, durable background work through a transactional outbox, backup and
  restore.
- **Cases and evidence.** Cases with purpose and scope, evidence with import origin, SHA-256,
  inert previews and hash-verified downloads, entities and relationships with review status,
  notes, exports with a manifest.
- **Public-source collection.** Public web pages, RSS/Atom feeds, GitHub accounts, username
  discovery across 58 platforms, and passive subdomain discovery in a network sandbox behind an
  egress gateway. Outcomes are explicit: no findings, partial, rate limited, authentication
  required, access denied, unavailable or parse error.
- **Evidence-grounded AI (optional).** Case-scoped hybrid retrieval, answers split into labelled
  claims with citations into hash-verified records, database-backed exact counts, summaries and
  relationship suggestions, local models by default, opt-in cloud generation per case.
- **Authorized imports.** WhatsApp chat exports and PDF documents processed by a worker with no
  internet route, with optional OCR as a separate labelled record.
- **Social platform connectors (fixture-tested).** Instagram, Telegram and YouTube through a
  capability model that states what each access method returns and what it never returns.
- **Analysis and reporting.** A timeline that keeps UTC, local and collection times apart, entity
  comparison, and self-contained HTML reports whose citations resolve offline.
- **Monitoring, teams and interoperability.** Monitors with durable scheduling and budgets, change
  detection against the last complete comparable collection, an in-app inbox with an optional
  webhook adapter that is off by default, administrator/analyst/viewer roles with case membership,
  a STIX 2.1 subset, an audit trail and retention with tombstones.

## Changes in the release-preparation pass

- Container images now carry `LICENSE` and `NOTICE.md` at
  `/usr/local/share/licenses/tracehollow/`, so a redistributed image carries its notices.
- Image names are parameterized (`TRACEHOLLOW_IMAGE_PREFIX`, `TRACEHOLLOW_IMAGE_TAG`), which lets
  verification stacks run without colliding with an installation.
- Graph labels no longer cut identifiers short: long labels wrap, and the canvas refits when the
  inspector opens or the window resizes, so nothing near the edge is clipped.
- Timestamps are composed explicitly in UTC instead of through `Intl.DateTimeFormat`. Engines ship
  different CLDR data, so Safari rendered `17 Sep 2026 at 18:29` where the server rendered
  `17 Sept 2026, 18:29`; the difference broke hydration and showed two different formats to two
  readers of the same case.
- New documentation: a documentation index, an installation-to-first-report tutorial, a
  demonstration-dataset guide, a troubleshooting guide, a connector authoring guide, an ADR index,
  a dependency and license inventory, and a performance and interface measurement record.
- `SECURITY.md` now describes the Phase 4 and Phase 5 surfaces and no longer claims the
  installation has a single administrator and no audit trail.

## Known limitations

- **Instagram is fixture-tested, not live-verified.** Business Discovery needs a Meta App Review
  that has not been filed yet, so the connector has never spoken to Meta's API.
- **YouTube transcripts are not available at all**, by design: the Data API does not serve them and
  the unofficial routes are excluded.
- Subfinder's live check was partial, because its second provider answered 403; it stays
  fixture-tested.
- Telegram's Bot API capability is fixture-tested; only the public web preview has a live check.
- The cloud AI provider is implemented against documentation and mocked responses and has never
  been called live.
- MISP and OpenCTI integrations are deferred.
- There is no tested downgrade path. To go back, restore the backup taken before upgrading.
- The audit trail is transactional but not tamper-evident.
- No independent security review, no screen-reader testing, no multi-tenant or internet-exposed
  deployment.
- Text handling is tested in Turkish and English only.

## Upgrading

There is no earlier release to upgrade from: this is the first. The upgrade path that was exercised
is the Phase 4 state → this release, with migrations 0006, 0007 and 0008 applied automatically by
the `migrate` job. Take a backup first
([../operations/backup-restore.md](../operations/backup-restore.md)).
